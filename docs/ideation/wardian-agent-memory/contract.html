Mission Brief · Draft · 2026-08-23

Wardian Agent Memory

A local-first, provider-neutral memory system that makes direct retention and session-start recall dependable before adding optional model-driven consolidation.

Confidence 96% Execution Sequential Default Direct memory on Consolidation Off

Problem

Provider continuity and conversation archives preserve runtime state and evidence, but neither gives a new agent session a concise, reliable understanding of durable preferences, decisions, lessons, and current project state.

Outcome

Every supported provider begins work with a bounded Wardian-owned memory brief. Agents save clear durable facts directly through a validated API, without requiring a second model call.

Decisions already made

Memory is not conversation logging

Memory stores normalized reusable records and durable evidence excerpts. Conversation links are optional provenance for deeper inspection.

Direct retention is the baseline

Agents strongly prefer saving clear preferences, decisions, corrections, and explicit requests. They never claim success without a Wardian acknowledgement.

Recall starts before work

Fresh sessions receive Stable memory and Current state. Resumed sessions receive a delta from the previous fingerprint.

Consolidation is ordinary automation

The opt-in curator is a normal bundled workflow with ordinary model selection, invocation, editing, and scheduling behavior.

Scope tiers

MVP

  • SQLite memory authority and audit history
  • Save, update, supersede, inspect, and remove APIs
  • Agent-wide and active-workspace scopes
  • Evidence excerpt, hash, and optional source links
  • Direct retention enabled by default

Full

  • Provider-neutral startup injection
  • Fresh briefs and resumed-session deltas
  • Deterministic context budget and stale labeling
  • Memory saved and Memory loaded events
  • Optional consolidation workflow

Stretch / deferred

Hybrid query-time semantic retrieval, local embeddings, cross-agent memory, and shared scopes. These follow only after startup recall is proven.

Execution track

1
Medium risk · blocking

Memory foundation

Build the SQLite authority, lifecycle APIs, scopes, evidence snapshots and links, audit history, and direct-retention instruction contract.

2
High risk · blocking

Reliable startup recall

Compile and inject bounded provider-neutral briefs, track fingerprints and resume deltas, and expose observable memory events.

3
Medium risk · non-blocking

Optional consolidation workflow

Add session-close invocation, curator selection, incremental archive cursors, strict structured output, and idempotent commits through a normal workflow.

Explicit non-goals

  • Provider-native history as durable memory
  • Conversation archives as the memory source of truth
  • Mandatory or hidden model-driven consolidation
  • Memory-specific workflow reset, compare, fork, or restore behavior
  • Automatic cascading deletion between conversations and memory
